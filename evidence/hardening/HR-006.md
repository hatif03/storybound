# HR-006: the image model painted words into a child's picture

Date: 10 Oct 2026. Found by looking at the frames of the first story video, not by a check: no promise covered it.

## Trigger

In the first illustrated story (`story-video-1`, trace `0fd459e70b5165e1455980c72c77f66d`, 8 pictures, 8 narration clips, cost estimate $0.358) the last page's picture had its caption painted into it: "The sun sets over the hill." and "Zuzu wiggles h..." (cut off). The prompt for that picture said "no text in the image". The story's receipt said "19 promises checked. 1 pages rewritten. All kept", so the receipt was true and the picture was still not acceptable for a child learning to read. Frame: `evidence/stories/bunny-sharing-1/` (page 8) and the screenshot in `evidence/screens/`.

## Diagnosis

Hypothesis: an instruction not to draw text is weak for an image model (naming "text" invites it). Fixing the prompt wording is not a guarantee, so the right fix is a check: a promise that a vision model verifies on the real picture bytes, with the existing repaint path when it fails (the pipeline already paints a picture once more when a picture promise fails). Coverage was the gap: of the picture promises, one checked that a picture exists and one that the hero matches, none looked for words.

## Change

- Commit `7b2f310` (Entire checkpoint `01M4JZX6VW56B56JRRDJPXQX7P`): new core promise `image_no_text` ("Pictures contain no words": score 1.0 if no readable words, letters, numbers or captions anywhere, 0.0 for any text, even partial or garbled; pass at 0.8), judged by the vision model like `image_matches_card`. The oath now has 22 promises (was 21).
- Commit `69e0acb` (Entire checkpoint `01M4K08HVYV2BDG3ABHGQ856DE`) follow-up: the promise is checked on **every** picture and the picture sampling knob cannot lower it. In the first run after the change only 3 of 8 pictures were sampled, which would have left the same hole.
- Tests: `test_a_picture_with_words_painted_into_it_fails_the_no_text_promise` (fake vision judge; the promise fails a picture with text, and still runs with sampling at zero) and the updated catalog count.

## Before and after

One story per side, so no rate is claimed:

- Before: `story-video-1`: 1 of 8 pictures had painted words; no promise noticed.
- After: `story-video-2` (trace `a7dd9ae1b8322bd4fc7d1529c05751e0`, 22 promises, 0 pages rewritten, 8 pictures, estimate $0.356): the check passed the 3 pictures it sampled; all 8 pictures were looked at by eye on a contact sheet and none had text. This run used the sampled version, so it shows the promise runs and the pictures were clean, not that it would have caught a bad one.
- Not measured: how often the image model paints words (1 in 16 pictures across the two stories), and how often the new check catches it. A proper test needs a set of pictures with and without words; the fake-judge test is the only proof of the repaint path so far.
